# A股行业—产业链—股票—ETF 总索引

> **用途：**这是全行业研究资料的统一入口。今后以维护本索引和映射表为主，不再无止境增加编号专题。
> **整理日期：**2026-10-12
> **边界：**只研究行业是什么、主要产品/服务、上下游关系，以及对应上市公司和ETF。除非用户明确提出，不主动扩展成短线行情、资金面、估值复盘等新专题。
> **数据纪律：**本文件中的股票/ETF是研究映射，不是推荐；ETF成分、权重、规模和流动性会变，必须标注数据日期并以基金公告/指数文件复核。

## 一、以后只维护这三层

1. **行业分类层：**用申万等分类体系作为目录；分类版本、行业代码和生效日期单独记录。
2. **产业链层：**记录行业细分环节、主要产品、上游投入、下游客户和最终需求。一个行业可以连接多条产业链。
3. **投资标的层：**每个细分环节对应上市公司及ETF/指数。公司要区分主营业务、部分业务敞口和仅有概念关联；ETF要记录跟踪指数与实际覆盖范围。

> 不把行业分类、产业链位置、市场主题混成一个标签。主题ETF可能跨越上下游多个行业；公司也可能同时经营多个环节。

## 四、如何维护一条映射

每个行业细分环节只维护一条主记录，建议字段如下：

| 字段 | 内容 |
|---|---|
| 行业分类 | 分类体系、版本、一级/二级/三级行业 |
| 细分环节 | 产业链位置及具体业务边界 |
| 主要产品/服务 | 公司或行业实际提供什么 |
| 上游 | 关键原料、设备、零部件、技术与服务 |
| 下游 | 直接客户行业、最终需求方 |
| 股票映射 | 代码、简称、业务角色、主营/部分敞口、证据日期 |
| ETF映射 | 代码、基金简称、跟踪指数、覆盖环节、成分/权重日期 |
| 证据 | 年报/半年报、基金合同、指数编制方案、定期报告链接 |
| 复核状态 | 已核验 / 部分核验 / 待核验 |
| 更新时间 | 最后核验日期 |

## 六、后续执行规则：停止扩写，转入整合

1. 不再按期数继续新开相似专题。
2. 先从已有专题提取行业定义、主要产品、上下游、公司和ETF，去重后合并到本总索引及行业卡。
3. 股票映射优先按主营业务和财报披露，不把概念股当成真实产业链供应商。
4. ETF映射优先按跟踪指数与实际成分，不以基金简称推断纯度；持仓数据必须注明日期。
5. 未经核验的公司、代码、ETF和权重标“待核验”，不为了填满表格而猜测。
6. 只在出现新分类、新上市公司业务变化、ETF指数/成分变化或用户提出新问题时更新相关映射，不定期制造新专题。
7. 现有专题保留为来源档案；本总索引是主入口，避免多份文件重复维护同一结论。
