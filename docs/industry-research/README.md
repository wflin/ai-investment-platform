## 研究目标

- 了解 A 股全行业的业务模式、上下游、需求来源和竞争格局。
- 识别宏观经济、政策、技术、价格、订单和库存如何传导至行业盈利。
- 统一比较行业景气、市场表现、估值和风险。
- 找到值得进一步验证的行业变化，而不是只追逐涨幅榜。
- 将研究结论映射到真实有相关收入的上市公司和适当 ETF。

## 基本原则

1. **先覆盖，再筛选。** 不只研究热门科技行业，周期、消费、医药、金融、公用事业和服务业同样纳入。
2. **分类与产业链分开。** 公司行业分类、上下游关系、市场投资主题是不同维度。
3. **事实、判断、假设分开。** 关键事实注明来源、发布日期、数据期间与口径。
4. **政策不等于业绩。** 必须验证资金落地、订单、交付和财务兑现。
5. **行业好不等于股票便宜。** 还要分析估值、预期和下行风险。
6. **不把资金流指标理解为凭空出现的资金。** 结合成交额、量价、广度、相对强弱和基本面。
7. **防止未来数据泄漏。** 历史研究只能使用目标时点已经公开且可获得的数据。
8. **不作确定性收益承诺。** 本手册是研究工具，不保证投资结果。

## 图表与图片规范

本手册不仅使用文字和表格，也可以在 Markdown 中嵌入图片、流程图和产业链图。后续研究遇到复杂关系时，优先用图帮助快速理解，再用文字解释关键结论。

- **流程与决策路径**：优先使用 Mermaid，便于版本管理和后续修改。
- **产业链、上下游关系、宏观传导路径**：适合用 Mermaid flowchart 或自制 SVG/PNG 图。
- **行业比较、景气指标、ETF/公司映射**：优先使用 Markdown 表格；只有图形能更清楚表达时再画图。
- **外部图片**：必须标注来源、发布日期（如适用）和授权/使用注意事项；不使用来历不明的图片。
- **仓库图片**：建议统一放在 `docs/industry-research/assets/`，使用相对路径引用，例如 `![产业链示意图](./assets/example-chain.svg)`。
- **图表不能替代证据**：每张图需注明数据口径、截止日期；示意图要标注“示意图”，不把假设关系画成已证实事实。

## 与现有平台的关系

本仓库已有行业分类、行业评分、政策映射、个股列表等后端接口。本手册定位为其背后的研究方法与知识层，不替代现有 API，也不要求为写文档修改业务代码。具体公司映射接入前，仍须核对现有接口、字段、数据源、版本与授权；不得仅凭文档描述推断接口细节。

## 分类口径

后续优先以申万行业体系作为平台研究入口，以便与现有功能衔接；正式一级、二级、三级清单必须从可核验的最新分类文件生成，并记录来源、版本与生效日期。证监会分类、申万分类、产业链主题和市场概念不是同一套体系，不强行一一对应。

## 每个行业的最低交付要求

- 定义、业务边界、商业模式
- 上游投入、中游环节、下游客户
- 需求、供给、价格、库存、产能、订单和利润指标
- 宏观变量与政策传导路径
- A 股公司及真实业务敞口、相关 ETF 与映射置信度
- 当前事实、分析判断、待验证假设
- 看多/基准/看空情景、风险与逻辑失效条件
- 来源、发布日期、统计口径、数据截止日期和复核日期
